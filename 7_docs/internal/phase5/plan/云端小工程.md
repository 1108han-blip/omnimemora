# 真实执行方案

## 阶段 1：先做“主仓对位审计”

让 OpenClaw 工程团队先不要写代码，先做一件事：

### 任务

把备份代码中的云工程改动，与**当前真实主仓**逐文件对位，输出一份差异确认单。

### 必查文件

- `5_connectors/adapter/main.py`
- `5_connectors/adapter/config.py`
- `5_connectors/adapter/cloud/__init__.py`
- `5_connectors/adapter/cloud/models.py`
- `5_connectors/adapter/cloud/client.py`
- `5_connectors/adapter/cloud/policy_loader.py`
- `5_connectors/adapter/cloud/flags_loader.py`
- `5_connectors/adapter/cloud/usage_reporter.py`
- `5_connectors/adapter/config/default_policy.json`
- `5_connectors/adapter/config/default_flags.json`

### 输出要求

必须输出三张表：

#### A. 可直接拷贝写入

备份代码与主仓无冲突，可直接迁移的文件

#### B. 需手工合并

主仓已变化，不能直接覆盖的文件

#### C. 禁止改动

发现会碰到 engine / runtime / 8765 协议边界的部分，必须列出并停止

---

## 阶段 2：先落“最小云接入骨架”

先只写入**最安全的部分**，不要一次全上。

### 第一批允许写入

这些基本可以先写：

- `cloud/__init__.py`
- `cloud/models.py`
- `cloud/client.py`
- `cloud/policy_loader.py`
- `cloud/flags_loader.py`
- `cloud/usage_reporter.py`
- `config/default_policy.json`
- `config/default_flags.json`

### 第二批允许改动

只允许改：

- `config.py`
- `main.py`

但 `main.py` 只允许改两处：

#### 1. optimize 前注入

policy = load_policy() or local_default  
flags = load_flags() or local_default

#### 2. optimize 后异步 usage 上报

report_usage_async(...)

### 明确禁止

- 不改 `4_core/logic/engine.py`
- 不改 `4_core/local-runtime/`
- 不改 8765 MCP 协议
- 不改 Final Compile Gate 既有主路径
- 不改 `memory.context` / `memory.search` 工具分工

这份审计报告也明确说这次方案没有碰这些红线，所以真实写入时也必须保持一致。

---

## 阶段 3：用“关闭云”模式先合并

这一步非常关键。

### 要求

真实产品代码写入后，默认配置必须是：

{  
  "cloud_enabled": false  
}

### 原因

先保证：

- 主路径不变
- Final Compile Gate 不受影响
- 新云层只是“预埋存在”，不是立即接管

也就是先做到：

> **代码已具备云接入能力，但产品默认行为不变**

这和审计报告里的风险控制一致：默认 `cloud_enabled=false`，云失败 fallback，本地照常运行。

---

## 阶段 4：真实链路验证

这一步不能省。

### 必跑 4 组测试

#### 1. 云关闭

- `cloud_enabled=false`
- OpenClaw 正常走 Final Compile Gate
- `memory.context` 正常
- token savings 正常增长

#### 2. 云开启但不可达

- `cloud_enabled=true`
- cloud_base_url 指向不可达地址
- 验证 fallback 到本地 default policy
- 主路径不报错

#### 3. optimization 开启

- `optimization_enabled=true`
- metrics / trace / 5173 正常
- usage 上报队列不阻塞请求

#### 4. optimization 关闭

- `optimization_enabled=false`
- 仍走统一入口
- 进入 passthrough
- 不做优化但系统可用

---

## 阶段 5：再决定是否启用真实云

只有上面全过，才进入这一步。

### 启用顺序

#### 第一步

只开 `/policy` 拉取  
不要先开 `/usage`

#### 第二步

再开 `/flags`

#### 第三步

最后开 `/usage`

这样出问题时最容易定位。
