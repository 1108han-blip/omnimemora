## 一、文档定位

本文件是当前阶段的**正式控制文档**。

目的不是增加新的产品原则，而是把已确认的产品决策转成可执行的收敛顺序，用来解决当前存在的 4 个未对齐现实：

- 主基线现实
- 已提交代码现实
- 工作区候选现实
- 运行实例现实

本文件用于回答三个问题：

1. 当前先做什么，后做什么
2. 每一步完成的定义是什么
3. 哪些内容本轮不做，避免继续扩大漂移

## 二、本轮收敛范围

### 2.1 纳入本轮

- 文档与环境收敛
- 控制面闭环收敛
- 路由 `on/off` 行为收敛
- 云端配置语义收敛

### 2.2 明确不纳入本轮

- `8765` 对外接口收口实施
- 自动自愈 / 自动拉起的正式实现
- compile / strategy 从 `18011` 的架构拆分实施

说明：

这些方向已经是正式目标，但本轮只做到“边界与顺序收敛”，不直接把它们扩大为新的实施面。

## 三、执行顺序

本轮固定顺序为：

> `M1 -> M2 -> M3 -> M4 -> M5`

禁止跳过 `M1 / M2` 直接继续控制面开发。

原因：

- 如果主基线和验证对象未先冻结，后续每一项“完成”都会出现验错对象的问题。
- 当前最大风险不是功能不存在，而是不同现实被混用。

## 四、里程碑定义

## M1：主基线冻结

### 目标

固定产品真相文档集合，清除当前主文档的上位真相失真。

### 完成条件

- 明确主基线文档集合
- 明确历史/失效文档集合
- README、产品定义、ADR 之间不再相互矛盾
- `5173` = 用户控制入口
- `18011` = 用户开启产品路由后的唯一产品数据入口
- `8765` = 内部 memory plane

### 产出物

- 单一主基线清单
- 已失效文档清单
- 术语统一口径

### Gate

**Gate A: 文档 Gate**

- README、产品定义、ADR 不再相互矛盾
- 不再引用不存在的上位真相文件

## M2：环境现实对位

### 目标

明确当前 repo、工作区候选、`~/.omnimemora/service/current` 三者之间的关系，固定验证对象。

### 当前冻结结论（2026-04-18）

- 当前 repo 代表**仓库现实**，用于承载已提交事实与后续文档收敛，不等于当前在线运行实例。
- 当前工作区代表**仓库候选现实**，可包含未提交或未跟踪改动，只能用于候选验证，不得直接当作已上线行为。
- 当前在线运行实例来自 `~/.omnimemora/service/current`，不是从当前 repo 直接启动；未额外声明时，`运行实例` 一律指向该外部运行实例。

### 验证对象分类（最小集合）

后续 Gate B 及其后的验证对象只允许使用以下两类：

- **仓库候选实例**：从当前 repo / 当前工作区显式启动、用于验证候选改动的实例。其验证结论只可落到“候选是否成立”，不可直接写成“当前在线实例已成立”。
- **外部运行实例**：位于 `~/.omnimemora/service/current` 的现行运行实例。其验证结论只可落到“当前运行实例行为”，不可反推“当前 repo 已具备相同行为”。

### 禁止混验规则

- 同一条验证记录必须只绑定一个验证对象分类，不得同时引用“仓库候选实例”和“外部运行实例”的观测结果拼接成一个结论。
- 若代码阅读基于当前 repo，而行为验证基于 `~/.omnimemora/service/current`，结论必须拆成两句分别记录，禁止写成“repo 已验证通过”。
- 若验证对象未在记录中写明“实例分类 + 实例路径/来源 + 结论适用范围”，该验证结论无效，不得用于 Gate B 之后的 gate 判断。
- 未显式重新声明前，不得把 `~/.omnimemora/service/current` 的成功行为当作当前工作区候选改动已生效的证据。
- 未显式启动仓库候选实例前，不得使用当前 repo 的代码差异去替代行为验证。

### 完成条件

- 明确当前运行实例来自哪里
- 明确“仓库候选现实”与“在线运行现实”是否一致
- 明确后续所有行为验证以哪个实例为准
- 明确禁止混验规则

### 产出物

- 运行来源说明
- 验证对象说明
- 禁止混验规则
- 验证对象登记与验收记录

### Gate

**Gate B: 环境 Gate**

- 验证命令与实例来源固定
- 不再混用仓库候选代码和外部运行实例做同一结论
- 每条验证记录都注明实例分类、实例路径/来源、结论适用范围
- 若验证对象为外部运行实例，必须明确写明其来源是 `~/.omnimemora/service/current`

## M3：控制面正式化

### 目标

将 `/agents/control*` 从候选现实收敛为正式仓库现实，固定双开关语义。

### 完成条件

- `/agents/control*` 进入正式仓库现实
- UI、adapter、runtime 三层语义一致
- 双开关语义固定：
  - `install/uninstall` = 接入层
  - `enable/disable` = 路由层
- `attach` 不默认等于启用产品路由
- `uninstall` 恢复原配置

### 产出物

- 控制面接口正式契约
- UI / adapter / runtime 一致口径

### Gate

**Gate C: 控制面 Gate**

- `/agents/control*` 在三层语义一致
- `enable/disable` 真正影响请求路径行为，而不是只写状态

## M4：路由行为闭环

### 目标

把路由 `on/off` 行为固定为正式产品行为，消除“状态存在但行为未切换”的断层。

### 完成条件

- `route=on` 进入 compile path
- `route=off` 进入 passthrough path
- `route=off` 不调用 compile
- 用户开启产品路由后，agent 不可自主绕过产品路径

### 产出物

- 行为闭环验证结果
- 关键接口验收记录

### Gate

**Gate D: 行为 Gate**

- `route=off` = passthrough
- `route=on` = compile path
- `uninstall` = restore original upstream config

## M5：云端策略语义收敛

### 目标

固定纯本地模式与云端增强模式的配置语义，避免云端能力继续污染产品入口定义。

### 完成条件

- 纯本地模式默认关闭云端策略更新
- 纯本地模式默认不上报数据
- 开启云端策略更新后，最小必要数据上报自动生效
- 上报范围固定为最小元数据集合
- 云端语义固定为“策略下发，本地执行”

### 产出物

- 云端配置口径
- 最小数据上报口径
- 默认值说明

### Gate

**Gate E: 云端 Gate**

- 纯本地默认不上报
- 开启云端策略更新后最小必要数据上报自动生效
- 上报范围不超出既定元数据集合

## 五、关键执行约束

### 5.1 顺序约束

- 必须先完成 `M1 / M2`，再继续控制面实现
- 不允许基于未冻结的运行实例继续扩大实现面
- `M3 / M4 / M5` 的所有验证记录都必须继承 `M2` 已冻结的实例分类口径

### 5.2 入口层约束

- 对 `18011` 的改动只允许增强其“接入编排层”职责
- 不得继续把 compile / strategy 与入口层深度耦合

### 5.3 接入实现约束

OpenClaw / Claude / Codex 的接入实现必须统一满足：

- `attach` 不默认等于 `route on`
- `uninstall` 恢复原配置
- `route on` 后 agent 不可自主绕过产品路径

### 5.4 云端边界约束

- 云端只能做“策略下发，本地执行”
- 不得把云端做成产品入口
- 不得把云端做成远端编译主控

## 六、完成定义

本文件中的任何“已完成”，都必须同时满足：

1. **仓库现实成立**
2. **可针对当前指定实例验证成立**
3. **验证记录已写明实例分类与结论适用范围**

只满足其中一条，不能视为完成。
